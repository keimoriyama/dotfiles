# 論文の種類ごとの構成と、査読で問われる点

ARR では、投稿時に貢献の種類を自分で申告する (CFP の contribution types)。主なものは次のとおり。

- 手法 (NLP engineering experiments)
- データ資源 (data resources)
- データ分析・モデル分析 (data analysis / model analysis and interpretability)
- サーベイ (surveys)
- ポジションペーパー (position papers)
- 再現研究 (reproduction studies)
- 理論 (theory)
- 低資源・低計算量の手法 (low-resource / low-compute)
- ソフトウェア (publicly available software or pre-trained models)

種類によって、章立ても査読者が確かめる点も変わる。原稿を評価するときは、最初に種類を決めてからこのファイルの該当節を読む。

## 数値の出典と注意

- 下の数値は、2022–2026 年の ACL long と EMNLP main の採択論文 11,011 本から集計した。
  - 種類はタイトルと Abstract からキーワード規則で推定した (`scripts/features.py` の `classify`)。
  - 推定の内訳: method 8,194 / resource 1,599 / analysis 1,079 / survey・position 139。
- 無作為に抜いた 40 本を目で確かめたところ、推定は約 8 割が正しかった。
  - 誤りは「分析や資源の論文を method とみなす」方向に偏っている。そのため、種類の間の差は実際より小さめに出ている。
- 「〜を含む論文の割合」は本文と付録の全文から正規表現で数えた近似値。
  - 例: "license" は機関名の "MIT" にも反応する。
  - 種類の間で比べるための目安として使う。
- 査読で問われる点は、ARR の査読ガイドラインと Responsible NLP Checklist の観点 (`review-criteria.md`、`submission-rules.md`) を、種類ごとに当てはめたもの。

## method: 手法の提案

**典型的な構成**: Introduction → Related Work → Method (手法名を章題にすることが多い) → Experiments → (Analysis) → Conclusion。この並びが 13.5% で最も多い。

- 手法の章と実験の章がそれぞれ本文の約 1/4〜3 割。
- 実験の章は Datasets / Baselines / Implementation Details / Main Results の小節に分ける。
- Abstract と Introduction で改善幅を数値で示すことが多い。

**査読で問われる点**
- 比較の公平さ (R1)
  - 強く、新しいベースラインと比べているか。
  - ベースラインにも提案手法と同じだけハイパーパラメータ探索をかけたか。
  - 計算量・モデル規模・データ量を揃えたか。
- 改善の確かさ (R5)
  - 複数のシードで平均とばらつきを示しているか。
  - 差が小さいときに有意性検定をしているか。
  - 採択論文でも有意性検定は 2 割にとどまり、査読で突かれやすい箇所になっている。
- ablation: 提案の各要素の寄与を切り分けているか。採択された method 論文の 64% が載せている。
- 一般化 (R2): データセット・モデル族・言語の範囲が、主張の範囲に見合っているか。
- 再現性 (M2, C1–C4)
  - ハイパーパラメータ、プロンプト全文、計算資源を書いているか。
  - LLM を使う場合、モデルの版と API の呼び出し日を書いているか。
- 効率を主張する場合、latency や FLOPs を実測で示しているか。
- 先回りの手当て
  - H5 (SOTA でない): 貢献が SOTA 以外のところにあるなら明記する。
  - H7 (単純すぎる): 単純さを利点として書く。

## resource: データセット・ベンチマーク・コーパス

**典型的な構成**: Introduction → Related Work → データ・ベンチマークの章 (名前を章題にすることが多い) → Experiments (既存モデルの評価) → (Analysis) → Conclusion。

- 構築手順の章 (収集 → アノテーション → 品質管理 → 統計) が中心になる。
- 付録が最も厚い (約 2,000 語)。アノテーションのガイドライン、プロンプト、事例を付録に置く。
- Ethics 節を置く割合が最も高い (51%)。

**査読で問われる点**
- 必要性 (G1): 既存のデータセットでは何が足りないのか。比較表 (規模・タスク・言語・ライセンスの違い) で示すのが定番。
- 品質 (M3)
  - アノテーター間一致率を示しているか。採択された resource 論文の 35% が示しており、他の種類の約 2 倍。
  - 品質管理の手順や、誤り率の推定を書いているか。
- データの記述 (B5, B6)
  - 規模、分割、ドメイン、言語、ラベルの分布を書いているか。
  - データシートやデータカードを付けているか。
- 権利と倫理
  - 元データのライセンスと利用条件 (B2, B3) を書いているか。
  - 個人情報への対処 (B4) を書いているか。
- アノテーターについて (D1–D5)
  - 募集方法と報酬を書いているか。報酬に触れる resource 論文は 44% で、他の種類より多い。
  - 指示文、同意、倫理審査を書いているか。
- ベンチマークとしての有用性
  - 既存の強いモデルで評価し、まだ解けていない (天井に達していない) ことを示しているか。
  - 人間の性能を示しているか。
  - データ汚染に対処しているか。
- LLM でデータを生成した場合: 生成物の検証、偏り、元モデルの利用規約に触れているか。
- 公開: 公開の方法、ライセンス、保守の予定を書いているか。Datasets スコア (Enabling〜Documentary) を意識する。

## analysis: 分析・評価研究・解釈性

**典型的な構成**: 骨格がばらつき、最も多い並びでも 5% にとどまる。

- 研究課題 (RQ) を Introduction で示し、それに対応させて章や節を立てる書き方が目立つ。RQ を明示する割合は他の種類の約 2 倍。
- 章題は "Experiments" が少なく (24%)、"Experimental Setup"、"Results"、"Discussion" が多い。
- 発見ごとに節を立て、節のタイトルに結論を書く書き方もある (例: "LLMs rely on surface cues")。
- hedge が最も多く (1000 語あたり 2.73)、強調語は控えめ。"we find / we observe" が多い。
- Abstract に数値を入れる割合は低い (15%)。発見を言葉で書く。
- Limitations が最も長い (約 170 語)。

**査読で問われる点**
- 問いの価値 (G1, H1): 答えが自明でないことと、答えが分かると何が変わるかを示しているか。
- 主張の範囲 (R2, R3)
  - 対象としたモデル・データ・プロンプトの範囲を超えて一般化していないか。
  - 相関を因果として書いていないか。
- 実験の統制
  - 交絡を除く対照実験になっているか。
  - 複数のモデル族と規模で確かめているか。
  - プロンプトの言い回しに対する頑健性を見ているか。
- 統計 (R5)
  - 有意性検定とばらつきを示しているか。採択された analysis 論文でも有意性検定は 29%。
  - 多重比較に配慮しているか。
- 評価の妥当性
  - 指標や LLM-as-a-judge が、測りたいものを測っているか (M1)。
  - 人手評価との一致を示しているか。
- 解釈性の研究: probing や介入の結果が、手法による副作用でないことを示す対照 (control task、ランダムなベースライン) を置いているか。
- 示唆: 発見から実務や今後の研究への示唆を書いているか。
- 先回りの手当て
  - H6 (結果が否定的): 否定的な結果から得られる知見を書く。
  - H13 (追加実験もできたはず): 主張に必要な範囲の実験は揃えておく。

## survey / position: サーベイ・ポジションペーパー

**典型的な構成**: Introduction → (Background) → 分類体系に沿った複数の章 → Challenges and Future Directions → Conclusion。

- Related Work の章を置かない (87%)。本文そのものが関連研究だから。
- 参考文献が非常に多い (中央値 121 本)。本文もやや長い (約 4,500 語)。
- 分類体系 (taxonomy) を示すものが 66%、今後の方向性を示すものが 76%。"Challenges and Future Directions" は定番の章題。
- 主語の "we" が少ない (1000 語あたり 4.6)。動詞は discuss / present / provide / summarize / argue。
- 段落が長めで (約 80 語)、Abstract に数値はほぼ入らない。

**査読で問われる点**
- サーベイ
  - 網羅性: 文献を集めた方法 (検索語、期間、採否の基準) を書いているか。
  - 時宜: 既存のサーベイとの違い、なぜ今必要かを示しているか。
  - 分類体系の妥当性: 分類の軸が明確で、相互に排他的か。図や表で示しているか。
  - 並べるだけでなく、比較・統合して知見を引き出しているか。
  - 未解決の課題と今後の方向性が具体的か。
- ポジションペーパー
  - 主張が明確で、反論を想定しているか。
  - 根拠 (文献、事例、小規模な分析) で主張を支えているか。
  - 立場の異なる研究を公平に扱っているか (G3)。
- 共通
  - 文献の正確さ: 引用が主張を支えているか (G5)。存在しない文献がないか (デスクリジェクトの対象)。
  - Limitations: 対象範囲の限定 (期間、言語、分野) を書いているか。

## その他の種類

統計を集計していない種類は、近い種類の節を流用し、次の点を足す。

- 再現研究: 元の論文との設定の違い、再現できなかった場合の原因の切り分け、元の著者への問い合わせの有無。
- 理論: 前提の明示と証明の完全さ (M5)。直観的な説明と小さな実証で補っているか。
- 低資源・低計算量: 計算量やデータ量の実測を、ベースラインと同じ条件で示しているか。
- ソフトウェア・ツール: 設計の動機、既存ツールとの比較、使いやすさの評価、公開とライセンス。Software スコアを意識する。
- 複数の種類にまたがる論文 (新しいデータセットと手法の両方など): 主張の中心になる種類を主にし、もう一方の観点も確かめる。
