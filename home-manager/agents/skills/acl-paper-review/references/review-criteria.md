# 評価の観点 (ARR の査読書式とガイドラインに基づく)

出典 (2026-10-17 取得):
- 査読書式: https://aclrollingreview.org/reviewform
- 査読ガイドライン: https://aclrollingreview.org/reviewerguidelines

ARR は書式と規定を周期ごとに改定する。投稿サイクルが変わったら出典を確認し直すこと。

## スコア

### Soundness (主張が証拠で支えられているか。0.5 刻み)

| 点 | 意味 |
| --- | --- |
| 5 | Excellent: その種類の研究として最も徹底したものの一つ |
| 4 | Strong: すべての主張に十分な裏付けがある。追加実験はあってもなくてもよい |
| 3 | Acceptable: 主な主張には十分な裏付けがある。細かい点は補強が必要 |
| 2 | Poor: 主な主張の一部に裏付けがない。技術面・方法論に大きな問題がある |
| 1 | Major issues: 出版に足る徹底さがない、または ACL の範囲外 |

Soundness を低くつけるなら、重大な欠陥を具体的に挙げなければならない。

### Excitement (主観的な面白さ。0.5 刻み)

| 点 | 意味 |
| --- | --- |
| 5 | Highly exciting: 推薦し、発表も聞きに行く |
| 4 | Exciting: 人に紹介し、発表も聞きに行こうとする |
| 3 | Interesting: 一部を紹介するかもしれない。時間があれば発表を聞く |
| 2 | Potentially interesting: コミュニティの誰かには響くかもしれない |
| 1 | Not exciting: *ACL コミュニティには響かない |

### Overall Assessment (0.5 刻み)

| 点 | 意味 |
| --- | --- |
| 5 | Consider for Award (上位 2.5%) |
| 4.5 | Borderline Award |
| 4 | Conference: *ACL 本会議に採択可 |
| 3.5 | Borderline Conference |
| 3 | Findings: Findings に採択可 |
| 2.5 | Borderline Findings |
| 2 | Resubmit next cycle: 大幅な改訂が必要だが、次のサイクルまでに可能 |
| 1.5 | Resubmit after next cycle: 次のサイクルまでには間に合わない大幅な改訂が必要 |
| 1 | Do not resubmit: 全面的にやり直すべき、または対象外 |

本会議に採るかは新規性とインパクトも加味して決まる。Findings は主に soundness と再現性で判断される。

### Reproducibility

| 点 | 意味 |
| --- | --- |
| 5 | 容易に再現できる |
| 4 | ほぼ再現できる。多少のばらつきはありうる |
| 3 | 苦労すれば再現できる。パラメータの記述が不十分、またはデータが入手しにくい |
| 2 | 再現は難しい。所属機関の外では入手できないデータに依存している、または詳細が欠けている |
| 1 | どれだけ努力しても再現できない |

Datasets / Software の評価 (公開すると書いてある場合): 5 Enabling / 4 Useful / 3 Potentially useful / 2 Documentary / 1 使えるものが出ていない。

### 自由記述の欄

Paper Summary / Summary of Strengths / Summary of Weaknesses (番号を付ける) / Comments, Suggestions, Typos / Limitations and Societal Impact / Ethical Concerns。

## 確認する観点

番号は査読ガイドラインでの記号に対応する。

### 主張 (Claims)

- **G1** 研究課題と貢献が明確か。Abstract・Introduction の最初の 1〜2 段落で、何を問い、何を示したかが読み取れるか。
- **R2** 主張の範囲が、サンプルと証拠の範囲に収まっているか。1 言語・1 モデル族・1 ベンチマークの結果を一般論として書いていないか。
- **R3** 仮説を結論のように書いていないか。
- **R4** 過剰な主張がないか。"significantly"、"consistently"、"state-of-the-art"、"first" などを、統計的な裏付けや網羅的な比較なしに使っていないか。
- 貢献の種類 (手法、資源、分析、再現研究など) を自分で正しく位置づけているか。SOTA を取らない研究も対象範囲に入る。

### 証拠 (Evidence)

- **M5** 技術的に正しいか。前提が明示され、証明が完全か (証明は付録に置いてもよい)。
- **R1** 分析が適切か。p-hacking、試行の都合のよい選択、ベースラインの調整不足がないか。
  - 提案手法とベースラインに、同じだけハイパーパラメータ探索をかけているか。
  - 比較する設定 (データ・モデル規模・計算量) が揃っているか。
- **R5** 必要な場面で統計的有意性やばらつきを報告しているか。シード数、標準偏差、信頼区間を示しているか。単一の実行・最大値・平均のどれなのかが明記されているか。
- **M4** モデルとベンチマークを選んだ理由が書かれているか。
- **M1** LLM による評価 (LLM-as-a-judge) を使う場合、その場面での妥当性を検証しているか (人手評価との一致など)。
- **M3** データの品質の問題を隠していないか。テストデータの汚染、アノテーションの一致率などが該当する。
- **G2–G5**
  - 先行研究を健全に使っているか (G2)。
  - 関連研究を公平に紹介しているか (G3)。
  - 鍵となる用語を定義しているか (G4)。
  - 引用が主張を実際に支えているか (G5)。
- ablation: 提案手法の各要素の寄与を切り分けているか。
- 誤り分析・事例分析: 数値だけでなく、どこで効き、どこで失敗するかを示しているか。

### 再現性

- **M2** 再現に足る詳細があるか。ハイパーパラメータとその選び方、プロンプト全文、計算資源、モデルの版などが書かれているか。
- コードとデータを公開するかどうかが明確か。公開しないなら理由が書かれているか。

### 倫理

- **T1** データ収集とアノテーションの問題 (同意、報酬、個人情報) がないか。
- **T2** 公開するものの利用条件 (ライセンス) が明確か。

### Limitations

- **H16** 正直に書かれた限界は、それだけで弱点として扱わない。著者の率直さは評価される。
- 主張の範囲に対応する限界が書かれているか。一般的な決まり文句だけになっていないか。

## 避けるべき査読の論法 (H1–H17)

自己レビューで弱点を挙げるときに、これらを根拠にしない。逆に、実際の査読者がこれらを持ち出しにくくなるよう、本文で先回りして手当てしておく価値はある。

| 記号 | 論法 | 先回りの手当て |
| --- | --- | --- |
| H1 | 結果が意外でない | 自明でない理由や、これまで検証されていなかったことを明記する |
| H2 | 結果が期待に反する | 結果の頑健性を示す |
| H3 | 新規でない (文献の提示なしに) | 最も近い先行研究との違いを明記する |
| H4 | 先例がない | 動機を丁寧に書く |
| H5 | 最新の SOTA に勝っていない | 貢献が SOTA 以外にあることを明記する |
| H6 | 結果が否定的 | 否定的な結果から得られる知見を書く |
| H7 | 手法が単純すぎる | 単純さが利点であることを示す |
| H8 | 査読者の好む方法論を使っていない | 方法論を選んだ理由を書く |
| H9 | 話題がニッチ | 一般化できる示唆を書く |
| H10 | 英語のみ / 英語以外のみ | 言語を選んだ理由と範囲を書く |
| H11 | 英語の誤り | 校正する (理解を妨げる誤りは本当の問題になる) |
| H12 | 文献 X が欠けている | 締切の 3 か月以上前に出版されたものであれば、本当の問題になる |
| H13 | 実験 X もできたはず | 主張に必要な実験だけは揃えておく |
| H14 | クローズドなモデル X と比べるべき | 主張に関わる場合に限り比較する |
| H15 | X をやるべきだった | 設計を選んだ理由を書く |
| H16 | 限界の記述を弱点とみなす | (査読者側の問題) |
| H17 | 被引用数が多いので正しい | (査読者側の問題) |

## 査読の書き方の原則

- **I1** 具体的に書く。節番号・表番号・文献名を挙げる。
- **I4** 専門的で中立的な口調で書く。皮肉や見下した言い方をしない。
- **I6, I7** まず斜め読みで期待を作り、判断を保留して精読する。関連研究の確認は、査読の下書きを書いた後にする。
- **I10** 追加実験は、主張に必要でない限り Weakness ではなく Suggestion に入れる。必要なら、なぜ必要なのかを書く。
