# コーディング規約

コードを書く前に設計をユーザーへ提示する。

成果物ごとに説明する対象を分ける。

- コードには How を表現する。
- テストコードには What を表現する。
- コミットログには Why を記録する。
- コードコメントには Why not を記録する。

## テスト

- テストフレームワークが存在する言語でコードを書くときは、テストも書く。
- 1つの関数につき、正常系と、境界値または異常系のテストを最低1つずつ書く。
- 数値計算が必要なテストは、簡単な計算ができるテストだけを実装し、評価は行わない。
- テストは pre-commit から実行する。変更時にテストを直接実行しない。
- シェルスクリプトにはテストを書かない。
